# Owon DGE1060 on the PSU stick — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Full control + read-back of the DGE1060 from the PSU stick, next to the PSU, behind the hub, robust from boot.

**Architecture:** New `owon_dge` component = `usb_host::USBClient` subclass (raw SCPI over bulk, MPS clamped to 64) + a table-driven SCPI engine mirroring `owon_psu` (one query in flight, set-once-then-requery). Pure parsing/formatting lives in `owon_dge_protocol.{h,cpp}` and is host-tested. Two side fixes: bounded PSU resync, and a USB client rescan for the dropped-NEW_DEV race.

**Tech Stack:** ESPHome 2026.6.5 external components (C++17, Python codegen), ESP-IDF USB host, host g++ tests, Python HIL check over the web API.

**Spec:** `docs/superpowers/specs/2026-10-21-owon-dge-design.md`

## Global Constraints

- Every published value is a read-back; never publish a requested value.
- The poll set contains only queries listed as answering in the spec.
- No sleeps/retries to dodge races; no polling for USB events beyond ESPHome's loop.
- No absolute paths in code/config. Minimal diffs; match surrounding style; SPDX `GPL-2.0-only` header on new files.
- Stick is reached over Wi-Fi only: web OTA `curl --interface wlp0s20f3 -F update=@<firmware.ota.bin> http://10.22.10.83/update`; web API via `--interface wlp0s20f3`.
- Generator output is unconnected: any set may be exercised live.
- Build after every change: `work/venv-host/bin/esphome compile owon-psu-stick.yaml`.

## Review Focus

1. A query the unit never answers slipping into the poll set → pending IN never completes; expect the engine to time out, resync, and the HIL check to show no stuck entities (Task 4 check: every entity reads back within 10 s of boot).
2. A set confirmed by its *first* read-back only (AM applies late) → expect re-query until match or settings-interval give-up, never a false "rejected" (Task 4 check: `Modulation=AM` reads back AM).
3. Exclusive modes: enabling burst while sweep on → both switches must reflect the device (sweep goes OFF) within one status poll (Task 4 check).
4. DGE unplugged/replugged at runtime → Connected OFF, then ON with all values re-read; PSU unaffected (optional: needs a hub replug at the bench; otherwise covered only by restart-button reboots).
5. Reply longer than 64 bytes (split over IN transfers) → reassembled by `\n` (Task 3 host test `split_reply`).

### Task 3: `owon_dge` protocol unit (host-tested)

**Files:**
- Create: `components/owon_dge/owon_dge_protocol.h`, `components/owon_dge/owon_dge_protocol.cpp`, `tools/owon_dge_protocol_test.cpp`

**Interfaces (Produces):**
```cpp
namespace esphome::owon_dge {
enum Setting : uint8_t { SETTING_OUTPUT, SETTING_LOAD, SETTING_SHAPE, SETTING_FREQUENCY, SETTING_AMPLITUDE, SETTING_OFFSET, SETTING_PHASE,
  SETTING_RAMP_SYMMETRY, SETTING_PULSE_DUTY, SETTING_PULSE_WIDTH, SETTING_PULSE_LEAD, SETTING_PULSE_TRAIL,
  SETTING_AM_STATE, SETTING_AM_DEPTH, SETTING_AM_SOURCE, SETTING_AM_FREQUENCY, SETTING_AM_SHAPE,
  SETTING_FM_STATE, SETTING_FM_DEVIATION, SETTING_FM_SOURCE, SETTING_FM_FREQUENCY, SETTING_FM_SHAPE,
  SETTING_FSK_STATE, SETTING_FSK_FREQUENCY, SETTING_FSK_RATE, SETTING_FSK_SOURCE,
  SETTING_SWEEP_STATE, SETTING_SWEEP_SPACING, SETTING_SWEEP_TIME, SETTING_SWEEP_SOURCE, SETTING_SWEEP_START, SETTING_SWEEP_STOP,
  SETTING_BURST_STATE, SETTING_BURST_MODE, SETTING_BURST_CYCLES, SETTING_BURST_PERIOD, SETTING_BURST_SOURCE, SETTING_BURST_GATE_POLARITY,
  SETTING_COUNT };
enum class Kind : uint8_t { NUMBER, BOOL, TOKEN };
struct SettingDef { const char *scpi; Kind kind; const char *const *tokens; uint8_t n_tokens; float wire_per_unit; };
const SettingDef &setting_def(Setting s);
// "SOUR1:FREQ?" etc. into buf; returns false if buf too small.
bool format_query(Setting s, char *buf, size_t len);
// Value in entity units (token index for TOKEN, 0/1 for BOOL) → "SOUR1:FREQ 320.000000".
bool format_set(Setting s, float value, char *buf, size_t len);
// Reply line (no \r\n) → entity units; NAN on malformed/unknown token.
float parse_reply(Setting s, const char *reply);
bool is_identity_reply(const char *reply);  // "OWON,DGE…"
}
```
Values pinned by the spec: shape tokens `SIN SQU PULS RAMP PRN DC`; source `INT EXT`; mod shape `SIN SQU RAMP PRN`; sweep spacing `LIN LOG`; sweep/burst source `TIM MAN EXT`; burst mode `TRIG GAT`; gate polarity `POS NEG`. `SETTING_PHASE` wire is rad, entity degrees (`wire_per_unit = π/180`). `SETTING_OUTPUT` uses `OUTP1`; all others prefix `SOUR1:`. Queries per spec table (`SETTING_PULSE_LEAD` → `PULS:TRAN`, `SETTING_PULSE_TRAIL` → `PULS:TRAN:TRA`). `SETTING_LOAD` replies ≥ 9.9e37 parse to `INFINITY`; `format_set(SETTING_LOAD, INFINITY)` → `OUTP1:IMP INF`.

  - `parse_reply(SETTING_SHAPE, "PULS") == 2`, `parse_reply(SETTING_SHAPE, "PUL")` is NAN
  - `parse_reply(SETTING_OUTPUT, "1") == 1`, `parse_reply(SETTING_OUTPUT, "x")` is NAN
